# Northern publication and retained GPU storage

The five required northern models prepare outside the visible world. Source
geometry changes only after the complete models and actual retained Core have
passed their private guards. `NorthCoreBridgeTerrainV309.ts` composes the small
bridge delta over the immutable original Core recipes. It independently checks
the three original variant controls and the reviewed delta, reuses every old
outside object and byte string, and combines disjoint original face ordinals.
The separate controller pins the derived recipe. Its additive outside meshes
keep their original Float32 positions, linear paint, normals and indices.
The original Core controller and its three controls remain unchanged.

Before an owned source geometry or instance-matrix reference changes, the Core
transaction invokes its optional `beforeSwap(object, kind)` callback. The same
callback is retained for rollback and revocation. Only changed references are
reported. `SceneGeometryGpuResidency.retireForRebind` and
`SceneGpuResidency.retireForRebind` retire registered, observed old handles while
the old attributes are still attached. Shared geometry retains its other owners;
foreign shared attributes block the transfer. Instance retirement precedes the
matrix swap because Three disposes the currently attached instance attributes.

Both managers preserve a stable render observer and update its registered
storage after the swap. This also preserves a queued GPU-warmup observer's
chain, without retaining inactive geometry observers. The publisher enqueues
the changed world into instance residency, geometry residency and warmup after
publication or restoration. No world-wide GPU sweep or budget increase occurs.

Readonly private retirement queries are true only during the real managers'
synchronous GPU disposal. New model/Core lifetime guards ignore this qualified
GPU retirement while continuing to reject authored resource disposal. CPU
geometry, precision, materials and visible detail survive retirement and
reupload unchanged. Tests use Three's real WebGL attribute, geometry and object
backends with a counting GL host; they verify identical reuploads, no handle or
observer growth over repeated commit/rollback, genuine warmup interaction,
shared-owner protection and authored-disposal rejection. They make no hardware
frame-rate claim.

`northernQuarterLoadingV309.ts` allows exact original surrounding packets to
render while required northern construction proceeds independently. Complete
recipes still arrive before any decode. Pending construction requests are
bounded separately for each visual family, and inactive late requests do not
start construction. The existing complete-model notification refreshes the
controller: only northern residents whose private admission changed are
reloaded. Before that admission, their original geometry, ink and navigation
remain unchanged. A model-loading error cannot reject or partially retire an
otherwise valid original packet. Revision, desired-region, mode and abort checks
remain in the surrounding controller.

Deferred park publication can overlap northern preparation. The northern factory
therefore stages the current `context.props()` roots until the set is stable,
rolling back obsolete unpublished plans. Preparation and live admission bind to
that current set. An extra detached park can prepare without revoking the live
park; its own privately registered synchronous commit scope permits the normal
complete-bundle gate only while that exact transaction adopts the new current
root. An unstaged current root closes admission and restores the predecessor
before any attempted Core or ink commit.

`completeCooperatively` offers a synchronous final-result callback. The northern
loader validates the prepared bundle, attaches it, retires the old exact owners
and records the complete live bundle in that final generator job. There is no
resolved-Promise gap in which a previously queued park publisher can miss the
live owner. The actual production regression swaps deferred parks during
staging, proves the retained source tree receives exactly eight required Y-word
changes, and checks a queued final-step park continuation, detached preparation,
private parent adoption, closed admission for an unknown current root and exact
rollback. Existing source recipes, transforms, rendering and loading limits are
unchanged.
