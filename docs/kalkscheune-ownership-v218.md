`DEBE01YYK0000BWc` and `DEBE01YYK000068w`, comprising five leaf parts.

The [Landesdenkmalamt entry](https://denkmaldatenbank.berlin.de/daobj.php?obj_dok_nr=09035269)

EPSG25833 `[390762.071197197,5820577.54103398]`, inside the Boq front house.
The two-storey description applies to the Johannisstraße corner house; the
courtyard buildings are described separately as two to three storeys. The
small `DEBE3DUWf5uFaNeg` hipped roof lies at the rear and is not this corner.

`build_kalkscheune_ownership_v218.py` replays only the original window recipe
on these five measured parts, using neighbouring source footprints for the
unchanged party-wall exposure test. It matches every complete quantized
position-and-linear-colour triangle signature against the existing external
`2_-2.drawn.json.gz` packet. All **1,458** old facade triangles match uniquely:
Boq 372, BWc 576 and 068w 510. These include surrounds, glazing, mullions and
sills; they are estimated openings, not surveyed architecture.

The receipt is applied through `siteOwnershipV209.ts` and the existing bounded
exact-packet transfer. An immutable positions/colours/indices fingerprint
guards it. It collapses only those index triples before the replacement
facade is displayed. No published packet, source surface, source ink,
navigation record, resident shell triangle or native Minecraft triangle is
removed or rewritten. Minecraft's original voxelized windows remain part of
its resident source geometry, and this drawn-only receipt does not claim to
replace them.

Validation regenerates the receipt from the original source and packet.
The runtime test checks every unselected index remains identical and that
native mode, resident shell IDs and changed packet bytes produce no transfer.
