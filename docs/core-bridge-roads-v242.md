# Core Spree bridge road fittings — v242

This is an additive Step 10 refinement of four existing authored bridges.
Their measured envelopes, supports, railings, lamps and sculptural details remain
unchanged. Existing raised pavement footprints at Moltkebrücke,
Hugo-Preuß-Brücke and Weidendammer Brücke receive a 12 cm wearing course and
a contrasting 22 cm inner curb strip. The new height follows the existing
segmented bridge camber; neither bridge axes nor approach extents move.
Kronprinzenbrücke already has stepped cycle lanes and pedestrian paths.

The retained `geo_data/regierungsviertel/osm.gpkg`, `roads` layer records
Friedrichstraße / Weidendammer Brücke way `6228081` with four lanes,
two in each direction. Konrad-Adenauer-Straße / Kronprinzenbrücke way
`188240631` has two lanes. The corresponding three/one broken lane separators
are added inside the existing carriageway. No inferred zebra crossings or
turn arrows are added. The dimensions of the dashes, curb strips and added
wearing course are presentation estimates, not individual measurements.

The existing named bridge source references and architectural bodies remain
authoritative. This change does not infer road use from unnamed bridge width
and does not affect railway or park bridge clusters.

## Lifetime, modes and walking

One 356-box drawn batch uses 27,056 instance bytes. Its independent orthogonal
Minecraft reading uses 1,565 merged surface boxes and 118,940 instance bytes.
Only one batch is visible in any mode. Native construction samples 0.5 m plan
cells and merges adjacent equal-height/color runs without a filled voxel volume.
Drawn mobile and desktop details are identical. No textures, animation, runtime
downloads or additional draw calls per object are introduced.

The unchanged bridge construction transaction owns both batches. The mode setter
runs after the existing shared-bridge visibility filter. Walking uses the same
finite paving rectangles and the same native cell interpretation; it retains
only the small fitted rectangle list, not the original terrain payload.

## Exact ordinary core bridge transfers

Twelve previously generic core clusters now receive the complete mapped source
bridge plans generated by `build_spree_bridges_v242.py`: Eberts-, Friedrichs-,
Gotzkowsky-, Hansa-, Lessing-, Liebknecht-, Luther-, Marschall-, Moabiter- and
Rathausbrücke, Gerickesteg and Wullenwebersteg. Each transfer requires the exact
complete previous world-cell set and unchanged sampled deck datum. Partial or
changed clusters, independently authored named profiles and both Monbijou arms
retain their existing ownership.

`CoreSpreeBridgesV242` decodes and checks the actual vertex/index counts of both
complete source mode families before retiring that one generic owner. If either
packet fails validation, its unpublished partner is disposed and the original
generic bridge is built normally. All source sheets and previous receipts remain
retained. Existing Luther ornamentation remains separately authored.

The viewer explicitly injects this required constructor into its drawn and cold
native bridge transactions. `IsometricCityWorld` keeps only a type import, so its
surface/building Worker cannot pull the core source payload or packet decoder
into the worker bundle. The existing worker byte ceiling remains unchanged.

The twelve decoded groups use 408,516 drawn buffer bytes and 2,509,326 native
buffer bytes (2,917,842 combined), with twelve meshes active per family. Native
triangles are independently axis-aligned. Packet parsing occurs once per mode
per construction and navigation retains only origins and finite floor/solid
records. A small weakly keyed holder permits navigation creation before geometry;
only successful geometry publication fills the later queried support records.
No callback captures the original terrain. Core sidewalks, curb and paint tops
share the same finite planes as the visible model; railing collision uses the
same stored plan and vertical interval.

## Validation

- Three focused checks verify bounded instance storage, independently orthogonal
  native transforms, family switching and actual raycast/physical curb and
  pavement height agreement on both sides of all three raised footways.
- The 67 existing pedestrian bridge, Humboldthafen and Weidendammer checks pass.
- TypeScript compilation passes.
- Four further core-source tests cover all twelve paired owners, every native
  triangle's axis alignment, actual rendered floor heights in both families,
  rail collisions, early navigation initialization, exact receipt guards and a
  deliberately invalid native packet retaining its old generic fallback, and
  cold-native to drawn reuse of the already built signature bridge root.

  filtered bridge checks because importing its full city fixtures used 6.7 GB
  of resident host memory. No result is claimed for that interrupted run.
